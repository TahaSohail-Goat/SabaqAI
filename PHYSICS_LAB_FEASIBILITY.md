**New components required:**

1. A versioned approved-experiment registry: immutable experiment ID, scope/source IDs, supported intents, human-reviewed equations, SI dimensions, parameter ranges, assumptions, evidence IDs/hashes/pages, capabilities, prediction prompts and allowed follow-up transitions. OCR/model output must never populate executable formulas automatically.
2. Pure deterministic TypeScript calculation functions, domain checks and reference cases. Return typed results and plot samples from the same calculation, with units, tolerances, assumptions and solver version. Server calculations are authoritative; browser animation interpolates the same result, with optional matching local preview.
3. A narrow tool dispatcher allowing only approved selection/parameter proposals. No `eval`, model code, shell, arbitrary SQL, network access, dynamic imports, expression parser or model-chosen tool URLs. Reject unknown tools/fields, unauthorized experiments and out-of-range values. A tool schema is input documentation, not execution authorization.
4. A Lab state machine: question → approved selection → prediction committed → calculated run → validated explanation → permitted follow-up. Changes to parameters create a new run. Selection and prediction cannot silently mutate after running. Request/run IDs, input hash, solver/evidence versions, optimistic concurrency and idempotency bind responses to the right run.
5. Separate Lab API contracts, Beam adapter, prompts, response validation and numerical-claim validation. Existing Ask review expects textbook-supported teaching; computed experiment results need a second provenance channel. A textbook citation must not masquerade as evidence for newly computed numbers.
6. Accessible controls, animation, labelled/unit-bearing graphs, result tables, replay/reset and failure/refusal states. Mobile touch/keyboard use, 360px layout, reduced motion, non-WebGL rendering, contrast and Urdu block direction need actual verification.
7. Owned `lab_sessions`/`lab_runs`-style persistence and migrations if resume/history is promised: prediction, normalized inputs, authoritative outputs, registry/solver version, evidence references, timestamps and explanation status. Names are proposals. Enforce RLS and owner checks, server-only output writes, curriculum changes, retention/deletion and stale-evidence handling. Never persist secrets or raw reasoning traces. New privileged functions need revoked PUBLIC execution and pinned extension paths where relevant.

### Making “AI must never invent results” enforceable

Free-form model prose plus a support-review model cannot provide an absolute guarantee: either model can invent a number, formula, capability or causal claim. Proposed safe contract: the model selects approved **observation/explanation IDs**, evidence IDs and result-field references. Code renders reviewed sentence templates and substitutes computed values, units, equations and stored citation metadata. Follow-ups come from registry capabilities. Reject unsupported selections rather than displaying unvalidated prose.

If unconstrained AI explanation is required, this becomes a probabilistic reliability target, which conflicts with the requested absolute rule. Resolve that product decision before implementation. Numerical string matching alone is insufficient: it misses wrong comparisons, units, signs and causal assertions. Templates also need review; deterministic does not mean scientifically correct.

## Performance and operations

**Proposed call budget, not measured:** selection 1 Beam call; prediction entry and deterministic calculation 0; explanation selection 1; independent semantic support/adequacy review 1 if retaining that policy.
